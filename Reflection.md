## Week 04 Reflection
After reviewing the instructor’s posted solution from Week 03 and comparing it to my own code, I’ve noticed several important differences that helped me understand how to improve. My code mostly worked and produced the correct output, but there were clear areas where my structure and style could have been better.
One thing I didn’t include in my original code was type hints. The instructor used type annotations like `height: int` and `-> None` in every function. This makes it easier to understand what the function expects and what it returns. I didn’t think of it at the time, but now I see how that small detail improves the clarity of the code. I plan to start using type hints in all my future assignments.
Another thing I noticed is that I used multiple return statements in a few places, especially in my draw_diamond function. For example, I returned early if the height was even. While that helped control flow quickly, the assignment actually asked for one and only one return per function. The instructor’s version handled even and odd values differently without using early exits. That showed me how to structure a function more cleanly while still handling edge cases.
My comments were okay but mostly explained what each line was doing. The instructor’s comments went further by explaining why certain logic was used, like how even and odd diamond shapes are related. That level of explanation helped me understand the design choices behind the code. I’ll try to include more of that thinking in my own comments going forward.
One thing I was proud of was my draw_hollow_square function. I solved it in a different way than the instructor, but the logic still worked. That gave me confidence that there’s more than one correct approach, as long as the structure and output are clear.
Overall, this comparison helped me think more about clarity, consistency, and clean structure. I’ll definitely carry those lessons into future code I write.
